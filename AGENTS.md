# Working on tree-sitter-varyk

This file is for anyone, human or AI agent, making changes to this
repository. [CONTRIBUTING.md](CONTRIBUTING.md) has the details; this is
the short list of rules.

## What this is

tree-sitter-varyk is the [Tree-sitter](https://tree-sitter.github.io)
grammar for [Varyk](https://varyk.com), a language for backend services
that compiles to Rust, and the query that highlights it. `grammar.js` is
the grammar, `queries/highlights.scm` the highlight query, `test/` the
corpus and highlight tests, and `src/` the parser `tree-sitter generate`
writes from `grammar.js`. Its first user is the Zed extension in
[`Varyk-Lang/varyk-editors`](https://github.com/Varyk-Lang/varyk-editors).
The design is in [`docs/specs/`](docs/specs/); read it before changing
what the grammar parses or how it names nodes.

## The gate

With the tree-sitter CLI 0.27.1, from the repository root, before every
pull request:

```sh
tree-sitter generate --abi 14
git status --porcelain -- src    # must print nothing
tree-sitter test
```

CI's `test` job runs the same and is a required check. CONTRIBUTING.md
also has `scripts/drift.sh`, the drift run against the compiler.

## Rules

- **The compiler is the authority.** The grammar parses every program
  the Varyk compiler accepts without an `ERROR` or `MISSING` node. It
  may accept programs the compiler rejects; it must never give a valid
  program a different structure (precedence, where an arm or a
  statement ends). A red drift run means the grammar is behind the
  compiler: fix the grammar, with a corpus case for the missed form,
  never the skip list.
- **Every syntax change in the compiler comes here.** A change to what
  the compiler's parser (`crates/varyk-syntax/src/parser/`) accepts
  needs a matching change to `grammar.js`, its corpus cases, and, when
  it adds a node, `queries/highlights.scm`.
- **`src/` is generated.** Regenerate it with `tree-sitter generate
  --abi 14` and commit it with every grammar change; never edit it by
  hand. ABI 14 because at ABI 15 `src/parser.c` carries
  `tree-sitter.json`'s version, so a release pull request, which bumps
  only that file, would fail CI's check that `src/` is current; Zed and
  nvim-treesitter load ABI 14.
- **Node names follow `tree-sitter-rust`** (`function_item`,
  `call_expression`, `match_arm`, ...), and so do field names. The
  item, string, and comment nodes are named in the Zed extension's
  queries: renaming one is a change to both repositories.
- **No bindings or packages until asked.** `tree-sitter.json` sets
  every binding to `false`; no `package.json`, `Cargo.toml`, or
  `setup.py`. Editors read the repository at a commit.
- **The CLI version is pinned.** It is named in the workflows, the
  README, CONTRIBUTING.md, and this file, and moves in one change for
  all of them, with `src/` regenerated by the new version.
- **Commits.** Conventional prefixes (`feat:`, `fix:`, `docs:`, ...),
  no `<` or `>` in subjects or `BREAKING CHANGE:` footers, and no
  attribution lines (no `Co-Authored-By`, no "Generated with").
- **Docs move with the change.** README.md, CONTRIBUTING.md, this file,
  and `docs/specs/` are updated in the same change whenever what they
  describe changes: the CLI version, commands, file layout, the drift
  rule, the release rule. Check them against the change before every
  pull request.
